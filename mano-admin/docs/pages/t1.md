# T1 match page

## Purpose

The `/t1` page collects T1 schedules, series results, set drafts, game statistics, and the official
Player of the Match in one match list.

## Finished-match POM

When a match is `FINISHED` and an official POM player has been synchronized, the player name is
shown directly on the collapsed match card so it can be found without opening set details. Upcoming
and live matches never show a POM. The latest finished match shows an official-POM pending badge
until the provider publishes the award instead of silently omitting the field or guessing a player.
The expanded match detail shows the full POM panel independently of any individual set.

The badge itself does not alter scores or notification behavior. Verify finished, unfinished,
blank-POM, and whitespace inputs, responsive card layout, the full test suite, type-check, and
production build.

## POM synchronization

POM synchronization must use a series-level official award when the provider exposes one. A
set-level MVP must not be treated as the series POM merely because it is the final non-empty value.
Provider text may contain wiki links, multiple recipients, or award labels and is normalized before
storage. If no series-level award is available, Mano keeps the POM empty instead of guessing from
KDA or damage. Existing match scores and set statistics remain unchanged.

Verify a single player, linked player text, multiple recipients, empty provider data, a losing T1
series whose POM belongs to the opponent, and delayed provider publication followed by a later sync.

## Provider request policy

Set-detail synchronization prefers the LoL Esports detail provider. When that provider returns a
complete set payload, Mano stores it and does not issue redundant Leaguepedia draft/stat requests.
Leaguepedia is a fallback only when the primary detail payload is unavailable. A Leaguepedia HTTP
429 is not retried immediately: Mano records the provider cooldown and asks the owner to retry after
the cooldown instead of spending a second request that is expected to fail.

POM comes from the series-level `MatchSchedule.MVP` field during the normal schedule sync; a
`single-game-draft` error is therefore a set-detail fallback error, not a POM parsing error. Verify
primary-provider success, fallback execution, 429 without `Retry-After`, and persisted cooldown.

## Set navigation

The expanded match card derives the played set count from the series score and existing game
numbers. It displays a synchronization control for every played set even after one set has already
been collected. Each collected set is an independent disclosure panel; the first starts open and
the remaining sets start collapsed. Verify partial collection, non-contiguous game numbers,
finished matches without detail rows, and independent set expansion.
