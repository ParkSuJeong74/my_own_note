# Mano 브랜드와 제품 비전

## 1. 브랜드 기원

**MyOwnNote → MyoNo → Mano**

- 이름: 나만의 노트, 마노
- 메시지: 마노와 함께 시작하는 당신만의 특별한 기록
- 도메인: `mano.io.kr`

Mano는 단순한 관리자 화면이나 기능 모음이 아니다. 사용자가 자신의 기록 방식과 생활
도구를 직접 구성하고, 어느 기기에서든 이어서 사용할 수 있는 개인 공간을 지향한다.

현재의 블록 워크스페이스 전환은 새로운 방향 전환이라기보다 초기 BI의 핵심이었던
“하나로 다 할 수 있는 나만의 노트”로 돌아가는 작업이다.

## 2. 제품 북극성

> 필요한 기능은 모두 갖추되, 빈 페이지에서는 아무것도 배우지 않아도 바로 쓸 수 있다.

Mano의 최종 경험은 다음 문장으로 판단한다.

- 내 기록을 내가 원하는 구조로 만든다.
- 메모에서 할 일, 일정, 가계부, 대시보드와 자동화로 자연스럽게 확장한다.
- 기능을 추가해도 기본 작성 경험은 단순하게 유지한다.
- 데스크톱에서 만든 구조를 모바일과 태블릿에서도 그대로 사용한다.
- 인터넷이 불안정해도 기록을 잃지 않고 연결되면 안전하게 동기화한다.
- AI는 사용자를 대신해 구조를 강제하지 않고 정리·검색·입력·자동화를 돕는다.

## 3. 브랜드 가치

### 나만의 것

페이지, 블록, 데이터베이스와 뷰를 사용자가 직접 조합한다. 제품이 정한 Todo 페이지나
Calendar 페이지에 사용자를 맞추지 않는다.

### 어디서든 이어지는 것

웹을 시작점으로 하되 Android 휴대폰, Galaxy Tab, macOS와 Windows 환경에서 같은
데이터와 편집 경험을 제공한다. 반응형 웹, 설치형 PWA와 오프라인 동기화를 먼저 검증한
뒤 네이티브 앱 필요성을 판단한다.

### 하나로 연결되는 것

메모, 파일, 체크리스트, 일정, 가계부, 블로그 운영, T1 기록, 자동화와 서버 상태가
분리된 제품이 아니라 같은 페이지 구성 요소가 된다.

### 안전하게 남는 것

암호화, 인증, 모니터링, 백업·복원, 내보내기·가져오기와 버전 이력은 부가 기능이 아니라
개인 기록 제품의 기본 조건이다.

### 조용하게 돕는 AI

AI는 선택 기능이다. 페이지 요약, 검색, OCR, 구조화, 태그 추천, 데이터 입력과 반복 작업
자동화를 지원하되 원본 기록과 사용자의 결정을 임의로 변경하지 않는다. 특정 AI 공급자나
개인 API 키에 제품 구조가 종속되지 않도록 provider 경계를 둔다.

## 4. 제품 단계

### 1ST — AI 개인 워크스페이스

현재 개발의 유일한 우선순위다.

- 페이지·폴더 계층과 블록 에디터
- 데이터베이스, 다양한 뷰, 필터·정렬·그룹과 템플릿
- 검색, 태그, 즐겨찾기, 최근 기록, 휴지통과 버전 이력
- 체크리스트, 달력, 위젯, 가계부와 사용자 정의 대시보드
- 파일·이미지·영상 첨부, 뷰어와 기본 편집
- 펜 입력과 그리기
- 오프라인 작성과 기기 간 동기화
- 백업·복원, 내보내기·가져오기
- 단축키, 앱·에디터 설정, 가이드와 사용 통계
- OCR과 AI 보조 기능
- 암호화, 인증, 모니터링과 장애 복구

기존 Mano의 T1, 블로그, Calendar, Todo, 자동화와 서버 관제는 이 워크스페이스가 실제
기능을 검증하는 첫 데이터 소스다. 최종적으로는 전용 UI가 아니라 사용자가 구성한 페이지로
표현한다.

### 2ND — 게시와 소셜

1ST가 일상적으로 안정되어 기존 기능 화면을 대체한 뒤에만 시작한다.

- 페이지를 블로그 형식으로 발행
- 해시태그, 실시간 업데이트와 반응 알림
- 짧은 스레드, 팔로우, 좋아요, 댓글과 재게시
- 차단, 신고, 스팸 방어와 공개 범위
- 텍스트·음성 대화, 멘션, DM과 그룹

2ND는 1ST의 개인 기록을 기본적으로 공개하지 않는다. 발행은 명시적으로 선택한 페이지의
별도 스냅샷과 권한 경계를 사용해야 한다. 소셜 기능 때문에 개인 워크스페이스의 단순성과
보안이 약해지면 진행하지 않는다.

## 5. 기능 완전성과 단순성

“기능이 모두 있다”와 “사용하기 쉽다”를 동시에 만족시키기 위해 세 층으로 노출한다.

1. 빈 페이지: 제목과 입력 영역만 보인다.
2. 빠른 추가: `/` 검색으로 블록, 데이터, 뷰와 AI 기능을 추가한다.
3. 고급 설정: 속성·필터·관계·자동화는 필요할 때만 단계적으로 펼친다.

처음 사용하는 사람은 텍스트와 Todo만 알아도 되고, 같은 페이지를 Calendar, 가계부,
프로젝트 보드나 운영 대시보드까지 확장할 수 있어야 한다. 템플릿은 완성된 전용 화면이
아니라 수정 가능한 일반 페이지를 생성한다.

| 확장 | 데이터 소스, 버튼, 자동화, 템플릿 | 기존 Mano 전용 화면을 사용자가 재현 |
| 이식성 | 표준 형식 내보내기·가져오기 | Mano를 떠나도 개인 기록을 소유 |

## 7. 지원 환경과 구현 우선순위

실제 검증 대상은 사용자가 보유한 환경을 기준으로 한다.

| 우선순위 | 환경 | 역할 |
| --- | --- | --- |
| 1 | macOS, Windows 데스크톱 브라우저 | 전체 편집·설정·데이터베이스 구성 |
| 2 | Android 휴대폰 | 빠른 기록, 검색, 확인과 완료 처리 |
| 3 | Android 태블릿 | 편집, 펜 입력, 분할 화면 |
| 4 | Ubuntu 홈서버 | 동기화, 저장, 자동화, 모니터링과 백업 |

초기에는 하나의 반응형 웹/PWA로 기능 계약을 검증한다. 플랫폼별 앱은 오프라인, 파일,
공유 메뉴, 위젯이나 펜 입력처럼 웹만으로 부족한 요구가 확인될 때 추가한다.

## 8. 에디터 경험 원칙

- 왼쪽 사이드바는 페이지 트리, 즐겨찾기, 최근 페이지, 검색, 휴지통과 설정을 제공한다.
- 사이드바는 접을 수 있고 모바일에서는 필요할 때만 연다.
- 중앙은 블록 편집기이며 키보드만으로 생성·변환·이동·삭제할 수 있다.
- 탭과 화면 분할은 여러 페이지를 함께 보는 핵심 데스크톱 기능으로 둔다.
- 사용자 설정은 글꼴, 폭, 테마, 단축키, 기본 블록과 동기화 상태를 포함한다.
- 터미널이나 개발자 기능은 일반 사용자 기본 UI와 분리된 선택형 고급 블록으로 검토한다.
- Calendar와 데이터 시각화는 기능뿐 아니라 매일 보고 싶은 시각 품질을 가져야 한다.

### 시각 정체성의 출발점

초기 BI의 시각 방향은 다크 차콜 배경, 화이트·그레이 텍스트와 블루 그라데이션
(`#007ACC` → `#005A9E`) 로고였다. 현재 Mano Admin의 그린 계열 운영 UI를 그대로
최종 브랜드로 확정하지 않는다. 블록 워크스페이스의 디자인 시스템 단계에서 다음을
함께 검증한다.

- 기록 내용이 가장 먼저 보이는 절제된 기본 화면
- 밝은 테마와 어두운 테마 모두에서 유지되는 Mano 고유 색상
- 모바일, 태블릿, 데스크톱과 스플래시 화면의 일관된 로고 사용
- 구매 폰트를 사용할 경우 앱·웹·상업적 배포 범위를 다시 확인한 라이선스 기록
- 꾸미기보다 장시간 읽기와 쓰기에 적합한 타이포그래피와 대비

## 10. AI 원칙

- AI 공급자는 교체 가능해야 하며 Claude, GPT 또는 로컬 모델을 선택할 수 있다.
- 개인 API 키 등록은 선택 사항이며 저장 시 암호화한다.
- AI가 읽는 페이지와 데이터 범위를 실행 전에 알 수 있어야 한다.
- 생성 결과는 미리보기 후 적용하고 원본 변경은 이력에서 되돌릴 수 있어야 한다.
- 비용, 실패, 처리 중 상태를 숨기지 않는다.
- 사진·문서 OCR은 추출 원본과 사용자가 수정한 결과를 구분한다.

## 11. 사업화와 소유권 원칙

초기 BI에는 도네이션, 광고, 기기·폴더·협업 제한, 콘텐츠 용량과 유료 편집 기능이
수익 후보로 기록되어 있다. 현재 단계에서는 수익화보다 개인용 제품 완성과 데이터
안전성을 우선한다.

향후 외부 사용자에게 제공하더라도 다음 원칙을 지킨다.

- 사용자의 기록 접근과 내보내기를 인질로 삼지 않는다.
- 광고가 개인 기록 내용이나 AI 입력을 추적하지 않는다.
- 무료 제한은 데이터 손실이나 복구 불가능 상태를 만들지 않는다.
- 결제, 협업, 공개 발행과 성인 인증은 별도의 법률·보안 검토 후 도입한다.
- 홈서버 자체 운영과 관리형 서비스의 데이터 소유권 차이를 명확히 안내한다.

## 12. 범위 판단 질문

새 기능을 만들기 전에 다음을 확인한다.

1. 개인 기록을 더 빠르게 남기거나 다시 찾게 하는가?
2. 사용자가 직접 구성할 수 있는 일반 기능인가, 또 하나의 고정 화면인가?
3. 기본 화면을 복잡하게 만들지 않고 필요할 때 발견할 수 있는가?
4. 데스크톱과 모바일에서 최소 핵심 동작을 제공하는가?
5. 오프라인·동기화·백업·이력에서 데이터를 잃지 않는가?
6. 기존 Mano 기능 제거에 실질적으로 기여하는가?

두 번째 질문에 답하지 못하는 전용 기능은 데이터 소스나 구성 가능한 블록으로 다시
설계한다.
