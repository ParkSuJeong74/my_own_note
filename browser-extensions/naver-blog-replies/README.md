# Mano Naver Blog Replies

1. Doppler `mano/prd`에 임의의 긴 `MANO_BLOG_INGEST_TOKEN`을 추가하고 Mano를 배포합니다.
2. Chrome `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드**합니다.
3. 이 디렉터리를 선택한 뒤 확장 팝업에 Mano 주소, 같은 토큰, 내 네이버 블로그 ID를
   저장합니다. 블로그 ID는 `blog.naver.com/내아이디`의 마지막 부분입니다.
4. 내 네이버 블로그 글이나 홈에서 **현재 글 댓글 수집**을 누릅니다. 네이버의 글 관리
   **댓글** 화면에서는 **댓글 관리 전체 수집**을 누르면 페이지네이션을 끝까지 따라가며
   받은 댓글을 한 번에 등록합니다. 관리 목록만으로 답글 관계를 확정할 수 없으므로 답글
   완료 판정은 실제 글 화면에서 **현재 글 댓글 수집**을 눌렀을 때 처리됩니다.
   최근 댓글의 `방금 전`, `N분 전`, `N시간 전`, `오늘 HH:mm`, `어제 HH:mm` 표기도
   수집 시각 기준의 절대시각으로 변환합니다. 댓글 행 안에 글 링크가 없으면 가까운 상위
   묶음의 링크·URL 속성까지 확인하며, 글 번호를 확인하지 못한 댓글을 블로그 홈 주소로
   저장하지 않습니다. 여러 iframe에 나뉜 댓글은 모두 합친 뒤 같은 글·작성자·작성 분
   기준으로 중복을 제거합니다. 상대시간 경계, 글 링크 누락, iframe 분할 결과를 회귀
   테스트로 검증합니다. 브라우저가 댓글 본문 iframe에 스크립트를 주입하지 못하는 경우를
   위해 바깥 관리 페이지에서도 `AdminNaverCommentManageView` iframe 주소를 네이버
   로그인 쿠키로 직접 읽으며, 양쪽 결과는 같은 중복 키로 합칩니다.
   과거 버전이 게시글 번호 없이 블로그 홈 주소로 저장한 자동 수집 기록은 다음 전체
   수집에서 제거하고, 정확한 게시글 주소가 확인된 댓글만 다시 등록합니다. 이 기록들은
   서로 다른 글의 댓글과 내 답글을 같은 글로 오판할 수 있어 완료 상태도 승계하지 않습니다.
   댓글 본문에서는 관리 목록의 `[글] 글 제목 -` 접두부를 제거하고, 네이버가 같은 문장을
   연속 렌더링한 경우 정확히 반복된 부분을 한 번만 남깁니다. 작성자 ID가 독립된 줄에
   없으면 닉네임 요소와 작성자 블로그 링크에서 ID·이름을 찾아 누락을 방지합니다.
   동일 댓글이 이미 Mano에 있으면 건너뛰기만 하지 않고 정리된 본문과 글 주소로 갱신합니다.
5. `내가 추가한 이웃`, `나를 추가한 이웃`, `서로이웃 신청` 화면을 각각 열고 팝업의 같은
   이름 수집 버튼을 누릅니다. 화면 자동 판별을 사용하지 않으며, 현재 화면에 맞는 버튼을
   사용해야 합니다. 확장은 해당 화면의 페이지네이션 링크를 끝까지 따라갑니다.
   한 탭의 결과는 다른 탭의 이웃을 사라진 관계로 처리하지 않습니다.
   네이버 바깥 관리 메뉴와 `papermain` iframe의 선택 상태가 어긋날 수 있으므로, 버튼을
   누르면 저장된 내 블로그 ID로 각 관리 endpoint(`BuddyListManage`, `BuddyMeManage`,
   `BuddyInviteReceivedManage`)도 직접 읽습니다. 이웃 ID는 블로그 링크뿐 아니라 네이버의
   `_param(https://blog.naver.com|아이디)` 클래스와 `blogId` 속성에서도 찾습니다. 요청한
   범위와 다른 메뉴가 선택됐거나 기본 설정 iframe이 남은 화면에서도 버튼의 범위만
   수집하며, endpoint 응답 실패와 빈 목록은 진단 정보로 구분합니다.
   같은 블로그 ID가 `내가 추가한 이웃`과 `나를 추가한 이웃` 양쪽에서 수집되면 두 범위를
   합쳐 `서로이웃`으로 집계합니다. 수집 순서에 따라 한쪽 관계가 덮어쓰지 않습니다.
   관리 endpoint의 페이지 이동이 일반 링크가 아니라 숨은 필드나 JavaScript인 경우에는
   응답에서 page 파라미터 이름을 찾고 `currentPage`, `page`, `pageNo`도 차례로 검증합니다.
   2페이지에서 새로운 이웃 ID가 확인된 파라미터로 새 ID가 없을 때까지 최대 100페이지를
   순회합니다. 정확히 50명에서 멈추는 첫 페이지 회귀를 테스트합니다.
6. 네이버 블로그 통계의 **일간 현황** 화면에서 날짜를 선택한 뒤 **성장 지표 동기화**를
   누르면 선택 날짜와 조회수를 읽습니다. 독립된 방문자 수가 표시된 경우에만 방문자도
   함께 읽습니다. 블로그 홈에서는 오늘 방문자와 전체 글처럼 이름과 숫자가 명확히 표시된
   값만 읽으며, 없는 값은 Mano의 직전 기록을 유지합니다. 일간 공감·댓글·이웃 증가와
   유입경로는 Mano의 누적 지표와 기준이 달라 수집하지 않습니다.
   이웃·서로이웃·댓글·답글 수는 Mano에 동기화된 데이터로 자동 계산합니다.
   실제 일간 지표가 `blog.stat.naver.com`의 `statmain` iframe에 있으므로 모든 프레임의
   결과를 비교하고, 바깥 관리 페이지에서는 통계 iframe URL도 로그인 쿠키로 직접
   읽습니다. DOM으로 파싱한 문서에서는 화면 좌표 대신 날짜 입력값과 본문 날짜를
   사용합니다. iframe 응답 실패 시 바깥 메뉴의 `조회수` 같은 문구를 지표로 오인하지
   않으며, 통계 프레임·직접 조회·값 없는 바깥 페이지를 회귀 테스트로 검증합니다.
7. 네이버 관리의 **글 관리 > 태그** 화면에서 **내 태그 수집**을 누릅니다. 태그 관리
   화면으로 판별된 iframe의 태그 링크·태그 행·선택 항목만 읽으며, 네이버 공통 메뉴와
   서비스 더보기 영역에 표시되는 `#서비스명` 링크는 수집하지 않습니다. DOM 변경으로
   태그 전용 요소를 확인할 수 없으면 페이지 전체의 `#...` 텍스트를 대신 저장하지 않고
   진단 정보와 함께 실패합니다. 정상 태그, 공통 메뉴가 함께 있는 화면, 태그 관리가 아닌
   화면을 확장 회귀 테스트로 검증합니다.

내 대댓글 여부는 닉네임이 아니라 댓글 작성자 링크의 블로그 ID로 판별합니다. 이미 Mano에
수집된 댓글도 다음 동기화에서 내 대댓글을 발견하면 자동으로 답글 완료 처리됩니다.

네이버 DOM 변경으로 댓글을 찾지 못하면 `popup.js`의 selector만 갱신합니다. 확장은 네이버
쿠키나 전체 HTML을 전송하지 않습니다. 수집 결과는 Mano에서 확인하고 이미 답한 댓글은
직접 완료 처리합니다.
