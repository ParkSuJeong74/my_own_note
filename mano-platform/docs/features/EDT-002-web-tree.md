# EDT-002 — Web folder and page tree

## Purpose

Expose the tested page-tree domain through the first interactive workspace screen. A user can create
root folders and pages, create pages inside a selected folder, and select an active node.

## Requirements

- The workspace shows active root nodes and their nested active descendants in deterministic order.
- A user can create a root folder or root page with a non-empty title.
- When a folder is selected, a new page can be created inside it.
- Selecting a page shows an editor placeholder associated with that page.
- Selecting a folder shows its name and child count without pretending it is a text document.
- Validation failures are announced accessibly and do not modify the tree.
- Buttons and tree items are keyboard-operable native controls.
- The screen must not claim persistence, autosave or synchronization; refresh currently resets data.

## Impact and boundaries

- `apps/web` becomes a client-side workspace shell backed by `@mano/editor-core` operations.
- IDs are generated by the browser through `crypto.randomUUID()` with a bounded fallback for tests
  and older environments.
- Data remains in React memory only. Local persistence and recovery are the next separate slice.

## Exceptions and deferred behavior

- Rename, move, reorder and trash exist in the domain but are not exposed in this first UI slice.
- Page body editing, routing and deep links are deferred.
- Authentication, API and multi-device synchronization are not involved.

## Verification

- Normal: create root folder/page, select nodes and create a page inside a selected folder.
- Failure: blank title displays an alert and creates nothing.
- Boundary: empty state and nested rendering.
- Regression: page selection never exposes the folder-only child action.
